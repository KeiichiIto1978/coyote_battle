# カード・山札・合計値計算仕様

## 目的

Version 1で使うカードをDomain層で表現し、再現可能な配布、複数ラウンドのカード追跡、特殊カードを含む合計値計算を提供する。

Domain層は`MonoBehaviour`、シーン、端末API、`UnityEngine.Random`へ依存しない。

## Version 1の山札

山札は次の36枚で構成する。

| カード | 枚数 |
| --- | ---: |
| 20 | 1 |
| 15 | 2 |
| 10 | 3 |
| 5、4、3、2、1 | 各4 |
| 通常の0 | 3 |
| 夜カード（0★） | 1 |
| -5 | 2 |
| -10 | 1 |
| ×2 | 1 |
| MAX→0 | 1 |
| ？ | 1 |

通常の0は数字カード、夜カードは特殊カードとして区別する。夜カード、×2、MAX→0、？は各1枚だけ存在する。

カードは生成後に種類と値が変わらず、山札内で個体を識別できる。数字カードは上表の数値だけを許可し、特殊カードは数値を持たない。

## 山札の領域

カードは常に次のいずれか1領域に存在する。

- ドロー山札
- 使用済み札
- 場札
- ？で引いた追加札

全操作の前後で、カード個体の重複と消失を許可しない。Version 1の既定山札では、4領域の合計が常に36枚となる。

## シャッフル

初期構築と再構築ではFisher-Yates方式でシャッフルする。乱数源は差し替え可能とし、同じ初期状態と乱数列から同じ山札順を得る。

乱数源は、指定された排他的上限に対して0以上かつ上限未満の値を返す。契約外の値が返った場合はコピー上の処理を破棄し、元の山札状態を変更しない。

## 配布とドロー

配布処理は上位層から重複しない順序付き参加者IDを受け取り、順番どおり各1枚を配る。残存参加者の抽出と脱落判定はApplication層の責務とする。

- 空の配布対象一覧は、山札を変更せず空の成功結果を返す。
- null、空文字、空白だけのID、重複IDは入力エラーとして拒否する。
- 全対象分を用意できない場合は部分配布しない。

？を解決する追加ドローは、場に？がある場合だけ行い、引いたカードを追加札領域へ移す。追加札を用意できない場合は、山札と計算結果を変更せず失敗する。

## 通常の再構築

要求枚数がドロー山札に不足する場合、場札と追加札を除き、残り山札と使用済み札を合わせて再シャッフルする。合わせても要求枚数に足りない場合は失敗し、全領域を変更しない。

夜カードがないラウンドの終了時は、場札と追加札を使用済み札へ移す。残りのドロー山札は維持する。

## 夜カードによる再構築

夜カードは合計値へ0を加算する。夜カードが場札または？の追加札として出た場合、合計値を確定した後のラウンド終了処理で全カードを集めて再シャッフルする。

再構築後は全カードがドロー山札にあり、使用済み札、場札、追加札は空になる。？で夜カードを引いた場合も同じ効果を適用する。

## 合計値計算

場のカードを次の順で評価する。

1. ？があれば山札から1枚引き、？を追加札で置き換える。
2. 追加札が特殊カードなら、その効果も計算対象へ加える。
3. MAX→0があれば、数字カードの最大値1枚だけを0として扱う。
4. 数字カードを合計する。通常の0と夜カードの加算値は0とする。
5. ×2があれば、手順4の合計を2倍する。
6. 夜カードがあれば、合計値とともに全山札再構築が必要であることを返す。

### MAX→0の境界値

- 同じ最大値が複数ある場合も、0にするのは1枚だけとする。
- 全て負数の場合は、最も0に近い最大値1枚を0とする。
- 最大値が通常の0の場合、結果は変化しない。
- 数字カードがない場合、結果は0となる。

空の場の合計値は0とする。同種特殊カードが複数ある場、同じ個体が重複する場、？から別の？を引く状態は、有効な36枚構成では発生しないため拒否する。

計算結果は、最終合計値、？で引いた追加札、夜カードによる全山札再構築の要否を含む。

## 失敗契約

- null、重複、不正なカード構成など呼び出し側の入力誤りは引数例外で拒否する。
- カード不足は`Try`メソッドの`false`で通知し、部分更新しない。
- 乱数源の契約違反や有効な山札では起きない矛盾は無効操作例外で通知し、元の状態を維持する。
- 回収対象がない状態での二重回収は`false`を返す。

## Version 1の対象外

仮面カードを使うスペシャルルールのSAME、DOUBLE、REVERSE、DRAW1、CHANGE、SHOTは実装しない。
