# NPC判断仕様

## 目的

強気型、慎重型、ギャンブル型、分析型のNPCが、自分から見える現在ラウンドの情報だけを使い、既存の宣言ルールで受理される数字宣言またはコヨーテ宣言を選択する。

NPC判断は`MonoBehaviour`、シーン、端末API、`UnityEngine.Random`へ依存しない。ゲーム進行はApplication層へ委ね、判断機能は手番、ライフ、カードを直接変更しない。

## NPC専用観測

観測は行動NPCごとの変更不能なスナップショットとし、次を含む。

- 行動NPCのIDとライフ
- 脱落者を含む固定5名のID、種別、ライフ、脱落状態
- 現ラウンドの残存参加者IDと人数
- 行動NPC自身を除く残存参加者の現在カード
- 現在の使用済み札をカード種別と値ごとに集約した枚数
- 現ラウンドで成功した数字宣言履歴と現在宣言
- 初手かどうか、数字とコヨーテの選択可否、次に宣言できる最小値

NPCからはユーザーのカードも見える。行動NPC自身のカードは、伏せ札や`null`の要素として残さずカード一覧から除外する。

実合計、実際のドロー順、ドロー山札、行動NPC自身の札、未解決の追加札、前ラウンド以前の宣言履歴は観測しない。使用済み札はカード個体IDや使用順を公開せず、現在の使用済み札領域にある種類・値別枚数だけを変更不能な一覧で公開する。元の一覧を変更しても観測は変化せず、公開一覧を呼び出し側から変更できない。

## 合計値の確率推定

Version 1は現在の使用済み札を記憶情報として使い、毎ラウンド次の方法で実合計の確率分布を作る。

1. 既定36枚から、現在見えているカードと現在の使用済み札を種類と値の枚数で差し引く。
2. 残りの各カードを行動NPCの伏せ札候補として枚数比で列挙する。
3. 場に`？`がある候補では、伏せ札決定後の残りカードから追加札も枚数比で列挙する。未使用候補が伏せ札1枚だけで追加札が不足する場合は、実際のDeckと同様に使用済み札を再構築後の追加札候補として列挙する。
4. 各候補を`？ → MAX→0 → 数字合計 → ×2`の順で評価する。夜カードは0として扱う。
5. 候補の枚数比を実合計ごとに集約し、確率の総和が1となる分布を返す。

宣言値`d`の成立確率は`P(実合計 >= d)`とする。夜カードまたは山札不足で全カードを再構築するとDomainの使用済み札領域が空になるため、次の観測も使用済み0の候補分布へ戻る。実際のドロー順や行動NPC自身の札は参照しないため、使用済み情報を加味した不完全情報の推定であり、実際の残り山札そのものは表さない。

## 共通の行動選択

各タイプは成立確率の閾値と最大上げ幅を決め、次の共通規則で行動する。

1. 現在値が`int.MaxValue`ならコヨーテを選ぶ。
2. 現在値より大きく、成立確率が閾値以上となる「支持可能な最大値」を求める。初手は現在値0として扱う。
3. 支持可能な最大値があれば、`min(支持可能な最大値, 現在値 + 最大上げ幅)`を宣言する。
4. 2手目以降で支持可能な値がなければコヨーテを選ぶ。初手で該当値がなければ、既存の合法条件を守るため1を宣言する。

上限判定は加算前の大小比較で行い、`int.MaxValue - 1`と`int.MaxValue`でオーバーフローさせない。数字行動は1以上かつ現在値より大きく、コヨーテ行動は成功した数字宣言が存在する場合だけ生成する。

## 思考タイプ

閾値が低いほど大きい数字を選びやすく、コヨーテが遅くなる。

| タイプ | 成立確率の閾値 | 最大上げ幅 |
| --- | ---: | ---: |
| 強気型 | 35% | +3 |
| 慎重型 | 75% | +1 |
| ギャンブル型 | 判断ごとに20%、50%、80%から等確率で選択 | 20%は+4、50%は+2、80%は+1 |
| 分析型 | 60%を基準に観測から補正 | 50%未満は+3、50%以上70%未満は+2、70%以上は+1 |

分析型は次を加減し、最終閾値を35%以上85%以下へ収める。

| 条件 | 補正 |
| --- | ---: |
| 自分のライフ1 | +15ポイント |
| 自分のライフ2 | +5ポイント |
| 直前宣言者のライフ1 | -10ポイント |
| 直前宣言者のライフ2 | -5ポイント |
| 直前2件の宣言上昇幅が5以上 | +10ポイント |
| 残存2名 | +10ポイント |
| 残存3名 | +5ポイント |
| 残存4名 | 0 |
| 残存5名 | -5ポイント |

上表にないライフ3、履歴1件以下、宣言上昇幅4以下は補正しない。

ギャンブル型はNPC判断専用の`IRandomSource`へ`Next(3)`を1回要求し、0、1、2を20%、50%、80%へ対応させる。範囲外の値は無効操作例外で拒否する。この乱数源は開始参加者とデッキ用の乱数源から分離し、NPC判断が将来のカード順へ影響しないようにする。

## バランスKPI

対象はユーザーが残存し、NPCから開始するラウンドとする。`RoundResult`または`GameOver`へ到達する前にユーザーの宣言手番が1回以上始まれば成功とし、固定した複数seedによる合計1000ラウンド以上で成功率80%以上を要求する。

seed 0〜99でゲーム終了まで複数ラウンドを進め、ユーザーは現在値を1ずつ上げる固定操作とした。NPC開始かつユーザー残存のラウンドだけを集計した結果、支持可能な最大値を直接宣言する旧方式は対象1025件中483件成功、47.12%だった。性格別の最大上げ幅を適用する方式は対象1072件中929件成功、86.66%となり、KPIを満たす。採用方式の対象には使用済み札あり800件、残存2〜4名489件を含む。

## 固定タイプ割当

| NPC | タイプ |
| --- | --- |
| `npc-1` | 強気型 |
| `npc-2` | 慎重型 |
| `npc-3` | ギャンブル型 |
| `npc-4` | 分析型 |

割当は次ラウンドと再戦後も変更しない。ユーザーと未知IDへタイプを割り当てない。

## Application連携

Application層は`Declaring`かつ現在手番が残存NPCの場合に限り、次の処理を1回行う。

1. 現在の参加者、配布、宣言履歴、Domainの使用済み札領域からNPC専用観測を生成する。
2. 固定割当された戦略へ観測を渡す。
3. 返された1行動を既存の数字宣言またはコヨーテ宣言APIへ適用する。

数字宣言後の手番更新とコヨーテ後の判定は既存ゲーム進行に従う。1回の呼び出しで次のNPC手番まで自動実行しない。連続実行、待ち時間、表示、演出はPresentation層の責務とする。

## 失敗契約

- nullの観測、推定器、必要な乱数源は引数例外で拒否する。
- 空白・重複・未知の参加者、ユーザーまたは脱落済みの行動者を拒否する。
- 残存者とライフ、カード所有者、宣言履歴が矛盾する観測を拒否する。
- 行動NPC自身のカード混入、他の残存参加者カードの欠落・重複を拒否する。
- 使用済み札のnull、0以下の枚数、重複したカード面、既定山札にないカード面を拒否する。
- 公開カードと使用済み札の合計が既定山札の種類別枚数を超える観測を拒否する。
- 1未満、単調増加でない、同一参加者が連続する宣言履歴を拒否する。
- 状態外、ユーザー手番、不正観測、無効な判断ではゲーム状態を変更しない。

## Version 1の対象外

- 使用済み札の使用順やラウンド別履歴、および学習
- 難易度、性格、タイプ割当の設定
- 機械学習
- NPC手番の連続実行、待ち時間、表示、演出
- 実際のドロー順や行動NPC自身の札を使う完全情報判断
