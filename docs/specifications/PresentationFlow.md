# 画面表示と操作

## 目的

Android端末でNPC4名とのゲームを開始し、宣言、判定、次ラウンド、最終勝敗まで操作できる2Dカードゲーム画面を提供する。

## 画面構成

- 単一の`Bootstrap`シーンでTitle、Battle、RoundResult、GameOverを切り替える。
- UI ToolkitのランタイムUIを使用し、基準解像度を1920×1080とする。
- 日本語表示はプロジェクトへ同梱したNoto Sans JPを全TextElementへ明示適用し、OSフォントへ依存しない。
- UI ToolkitのデフォルトテーマをPanelSettingsに設定し、ボタンと入力欄を実行環境で正しく描画する。
- 画面は横向きに固定し、Presentationが`Screen.safeArea`を基準解像度へ換算して余白へ反映する。
- 1280×720、1920×1080、2400×1080を検証対象とする。
- 背景、NPC4名、カード表面8種、カード裏面、エンブレムは`Assets/CoyoteBattle/Resources/Art`の画像を使用する。

## タイトルと開始

- タイトルにはゲーム開始操作を1つ表示する。
- 開始時は新しい`GameFlowService`をゲーム用乱数とNPC用乱数の別インスタンスで生成する。
- 前ゲームの入力、エラー、結果、保留中のNPC処理は引き継がない。

## 対戦画面

- NPC4名を上部、ユーザーのカードと操作欄を下部へ配置する。
- 表示名は「あなた」「NPC 1（強気）」「NPC 2（慎重）」「NPC 3（ギャンブル）」「NPC 4（分析）」とする。
- NPC画像は、強気な若い女性、慎重な若い女性、ギャンブル型の少年、分析型の老人男性というオリジナルのアニメ調キャラクターで構成する。
- NPC画像は各NPCパネルの横幅を使用し、残りの高さへ縦横比を維持して収める。名前、ライフ、カードとは領域を分けて重ねない。
- 現在手番ではNPC画像を維持したままパネル枠を強調する。脱落後もNPC画像と「脱落」表記を併記する。
- NPC画像を読み込めない場合も、名前、ライフ、カード、操作およびゲーム進行を維持する。
- ユーザーのカードは判定まで画像付きの伏せ札として表示する。
- NPCのカード、全員のライフと脱落、現在手番、現在の宣言値、直前の宣言者を表示する。
- 中央の行動バナーは最新の1手だけを大きく表示し、宣言履歴一覧は設けない。
- 特殊カードは「0★」「×2」「MAX→0」「？」と表記する。

## カード情報

- ユーザー手番中は「カード情報」から対戦画面右側のパネルを開ける。
- パネルには全36枚を15のカード表示単位にまとめ、「カード」「初期」「使用済み」を1行ずつ表示する。通常の0は「0」、夜カードは「0★」として別行にする。
- 使用済みは現在の使用済み札だけを数え、進行中ラウンドの場札と？の追加札はラウンド終了まで含めない。
- パネル表示中は数字入力、数字宣言、コヨーテを無効化する。「閉じる」で同じラウンド、手番、入力内容へ戻る。
- NPCの思考中と行動表示中はカード情報ボタンを無効化し、NPC進行の待機時間と処理順を変更しない。
- パネルは画面内に1つだけ構築して開閉時に再利用し、ラウンド結果、ゲーム終了、タイトルへの遷移時は閉じる。
- ドロー順、ユーザーの伏せ札、未公開の残り枚数は表示しない。
- 1280×720、1920×1080、2400×1080とSafe Area相当余白で、対戦欄とカード情報パネルを重ならない領域へ配置する。全行はパネル内で縦スクロールできる。

## 数字入力とコヨーテ

- 数字入力欄は1〜10文字を欠落や周辺要素との重なりなく表示し、入力、追加入力、削除、全削除を即時に画面へ反映する。
- 入力中は全角数字、符号、小数、空白だけの入力も隠さず表示し、送信時に既存の入力検証で拒否する。
- 入力欄内部のテキスト要素へ同梱Noto Sans JP、不透明な暗色文字、明るい背景を明示適用し、文字と背景のコントラスト比を4.5:1より大きく保つ。
- キャレットは入力背景と、選択背景は選択中の文字と識別できる不透明色または十分に濃い色で表示する。
- 無効状態は有効状態と異なる背景と枠線で操作不可を示し、既存値がある場合も不透明な文字色で判読可能にする。
- 入力前後の空白を除いた半角10進整数だけを受け付ける。
- 有効範囲は1〜`int.MaxValue`で、直前宣言より大きい値だけをApplicationへ送る。
- 空、全角数字、符号、小数、0以下、範囲外、直前宣言以下は送信せず、入力欄の下へ理由を表示する。
- 宣言履歴がなければコヨーテを無効化する。
- 直前宣言が`int.MaxValue`なら数字宣言を無効化する。
- ユーザー手番以外、NPC待機中、結果表示中、遷移中は宣言操作を無効化する。
- 操作受理時に即座に無効化し、同じ操作を複数回Applicationへ送らない。

## NPC進行

- NPC手番では対象パネルの枠を強調し、参加者名と「考え中…」を表示して0.8秒待ち、1回だけNPC手番APIを呼ぶ。
- 数字宣言後は中央の行動バナーへ「NPC名：Nを宣言！」を表示し、入力を無効にしたまま1.0秒保持する。
- コヨーテ宣言後は中央の行動バナーへ「NPC名：コヨーテ！」を表示し、Battle画面で1.0秒保持してからRoundResultまたはGameOverへ遷移する。
- 次もNPCなら同じ処理を繰り返し、次の思考表示で状態表示を置き換える。行動バナーは最新の1手だけを維持する。
- ユーザー手番へ戻った場合は、現在の宣言値、直前の宣言者、最新のNPC行動を確認できる状態で入力を有効化する。
- 思考中と行動表示中の待機方法は差し替え可能とし、時間順序をPlayModeテストから制御できるようにする。
- NPC連続進行Coroutineは同時に1本だけ実行し、Applicationが行動を拒否した場合は同じ手番を再試行しない。
- 画面破棄、再戦、結果遷移、タイトル復帰、ゲーム状態置換時はCoroutineを停止し、世代番号を更新して古い処理を無効化する。

## 結果とゲーム終了

- RoundResultは履歴一覧を設けず、敗者を最も大きく、次に実合計、最終宣言値、最終宣言者、コヨーテ宣言者の順で明瞭に表示する。全配布札と？の追加札、ライフ、脱落も併記する。
- 継続時だけ「次のラウンドへ」を表示し、明示操作で開始する。
- GameOverは最終結果の上へ勝利または敗北ダイアログを重ねる。
- 「もう一度遊ぶ」は新しいゲームを開始し、「タイトルへ戻る」はゲーム状態を破棄する。
- Version 1では対戦途中とラウンド結果にタイトル復帰を表示しない。

## 画像素材

画像素材はAI画像生成で作成した同一画風のオリジナル素材で、第三者のロゴや文字を含めない。キャラクター素材シートから4名のポートレートを切り出す。カード素材シートから正数、0、負数、夜、×2、MAX→0、？、裏面を切り出し、正確な値と記号はUIテキストとして重ねる。背景は横長のカード卓画像を使用する。

Noto Sans JPはSIL Open Font License 1.1に基づき同梱し、ライセンス本文を`Assets/CoyoteBattle/ThirdPartyNotices/NotoSansJP-OFL.txt`へ収録する。

## テスト

- EditModeで入力境界、固定表示名、特殊カード表記、本番乱数の範囲を検証する。
- PlayModeでBootstrapからタイトル画面を生成できること、ゲーム開始後にBattleとユーザーの伏せ札を表示できることを検証する。
- PlayModeで数字入力欄への実キー入力、Backspace、全削除、選択、キャレット色、有効・無効状態、不正形式の表示と既存エラーを検証する。
- 数字入力欄の1文字と10文字は、1280×720、1920×1080、2400×1080およびSafe Area相当余白で欠落や周辺要素との重なりがないことを検証する。
- PlayModeでNPC 4名の画像割当、正の描画幅・高さ、現在手番の枠強調、脱落表示、内部要素と隣接パネルの非重複を検証する。
- PlayModeでNPC 2〜4手の思考と数字宣言が順番どおり一度ずつ表示され、各行動を1.0秒保持することを検証する。
- PlayModeでNPCのコヨーテ表示後にRoundResultまたはGameOverへ遷移すること、待機中の入力無効、行動拒否時の再試行防止、画面破棄時のキャンセルを検証する。
- NPC行動バナーと結果の優先情報は、1280×720、1920×1080、2400×1080およびSafe Area相当余白で欠落や重複がないことを検証する。
- EditModeでカード情報の初期36枚、通常0と0★の区別、進行中ラウンドを除外した使用済み集計、通常回収と再構築後の値、公開一覧の変更不能性を検証する。
- PlayModeでカード情報の全15行と合計、開閉中の宣言操作、同じ手番への復帰、重複パネル防止、NPC待機中の無効化、通常ラウンド後の使用済み更新を検証する。
- カード情報パネルは、1280×720、1920×1080、2400×1080およびSafe Area相当余白で対戦欄と重ならず、全15行を保持することを検証する。
- 1280×720、1920×1080、2400×1080とSafe Area相当の余白はPlayModeでレイアウトを検証し、実機またはGame Viewでも最終確認する。
