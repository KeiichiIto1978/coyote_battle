# ゲーム進行仕様

## 目的

Version 1のカード配布、宣言、判定、ライフ減少、脱落、次ラウンド、ゲーム終了をApplication層で一貫して進行する。Domain層のカード、参加者、宣言ルールを重複実装せず調停し、Presentation層とNPC判断へ変更不能な状態を提供する。

Application層は`MonoBehaviour`、シーン、端末APIへ依存しない。

## 参加者と固定リング

ゲームは常に次の固定5名で開始する。

- ユーザー: `user`
- NPC: `npc-1`、`npc-2`、`npc-3`、`npc-4`

全員の初期ライフは3であり、固定リング順は`user → npc-1 → npc-2 → npc-3 → npc-4 → user`とする。巡回時はライフ0の脱落者を飛ばす。

第1ラウンドの開始参加者は、差し替え可能な`IRandomSource`を使って固定5名から一様に選ぶ。ゲーム開始処理は最初に開始位置を取得し、その後に同じ乱数源で既定デッキをシャッフルする。これにより、同じ乱数列から開始者と配布結果を再現できる。

## 状態

外部から安定して観測できる状態は次の4つとする。判定途中の状態は公開しない。

| 状態 | 意味 | 受理する操作 |
| --- | --- | --- |
| `NoGame` | ゲーム状態なし | 新規ゲーム開始 |
| `Declaring` | 配布済み・宣言受付中 | 現在手番の数字宣言、コヨーテ宣言、タイトル復帰 |
| `RoundResult` | 判定済み・結果表示中 | 次ラウンド開始、タイトル復帰 |
| `GameOver` | 最終勝敗表示中 | 新規ゲーム開始、タイトル復帰 |

初期状態は`NoGame`である。状態外の操作は`false`を返し、ラウンド番号、手番、宣言、カード、ライフ、結果、勝敗を変更しない。

## ゲーム開始と配布

新規ゲーム開始は`NoGame`と`GameOver`だけで受理する。

1. 全員がライフ3の固定5名を新規生成する。
2. 注入乱数から第1ラウンド開始者を選ぶ。
3. 同じ注入乱数で36枚の既定デッキを生成・シャッフルする。
4. 開始者を先頭に固定リングを巡回し、残存参加者へ1枚ずつ配る。
5. 同じ順序付き残存参加者IDから宣言フェーズを生成する。
6. ラウンド番号1、開始者と現在手番を同じ参加者にし、`Declaring`へ遷移する。

配布対象、宣言参加資格、開始者、現在手番の候補には、同じラウンド開始時点の残存参加者集合を使う。全対象へ配布できない場合は部分配布しない。

## 手番と宣言

現在手番の参加者だけが宣言操作を行える。

- 初手は成功した数字宣言がないため、1以上の有効な数字だけを宣言できる。
- 2番手以降は直前より大きい数字またはコヨーテを選べる。
- 有効な数字宣言後だけ、固定リング上の次の残存参加者へ手番を進める。
- 無効な数字、現在手番以外、未登録参加者、Domainが拒否した操作では手番を進めない。
- `int.MaxValue`の宣言後は数字を競り上げられないため、次の現在手番はコヨーテだけを選べる。
- 有効なコヨーテ宣言後は手番を進めず、追加の宣言を受理しない。

参加者IDのnull、空文字、空白は入力エラーとして引数例外で拒否する。不明な参加者IDは状態不変で`false`を返す。

## ラウンド判定

有効なコヨーテ宣言を受理すると、次の処理を同期的に1回だけ行う。

1. 配布カード、最終数字宣言、コヨーテ宣言者を保持する。
2. カードDomainで`？`の追加札と全特殊効果を解決し、実合計を計算する。
3. 宣言Domainへ実合計を渡し、ラウンド敗者を決定する。
4. カードDomainで場札と追加札を回収する。
5. 参加者Domainで敗者のライフを1だけ減らし、脱落を確定する。
6. ユーザー敗北またはユーザー勝利を判定する。
7. 判定素材と反映後状態を変更不能な結果スナップショットへ保存する。
8. 終了条件未達なら`RoundResult`、到達なら`GameOver`へ遷移する。

通常ラウンドでは場札と追加札を使用済み札へ移す。夜カードが場または追加札にある場合は全36枚を再構築し、次回配布時にドロー山札が不足した場合は残り山札と使用済み札を再構築する。詳細はカード仕様に従う。

有効な既定ゲームでは合計計算、回収、ライフ適用が失敗しない。不変条件違反を検出した場合は無効操作例外とし、ライフだけを減らした確定状態へ遷移しない。

## ラウンド結果

結果スナップショットはカード回収後も次を保持する。

- ラウンド番号
- 配布先と全配布カード
- `？`で引いた追加札
- 特殊効果適用後の実合計
- 最終数字宣言者と宣言値
- コヨーテ宣言者
- 敗者
- ライフ減少後の全参加者状態
- この判定で脱落した参加者
- 未確定、ユーザー勝利、ユーザー敗北のいずれかの勝敗

`RoundResult`と`GameOver`では数字宣言、コヨーテ、重複判定を拒否する。結果は次ラウンド開始、新規ゲーム開始、タイトル復帰のいずれかで明示的に破棄されるまで保持する。

## カード情報の公開

`Declaring`ではユーザー自身のカード内容を伏せる。配布先と伏せ札であることだけを公開し、カード個体識別子、種類、値は公開しない。NPCカードは読み取り専用で公開する。

`RoundResult`と`GameOver`では、結果スナップショットからユーザーを含む全カードを公開する。Application層はPresentation層へ変更可能なDomain状態を渡さず、参加者、配布カード、宣言履歴、結果の一覧を読み取り専用で返す。

## 次ラウンド

次ラウンド開始は`RoundResult`だけで受理する。

- 敗者が残存する場合は、その敗者を開始参加者とする。
- 敗者がライフ0で脱落した場合は、固定リング上で敗者の次にいる残存参加者を開始者とする。
- 脱落者が連続する場合も、次の残存参加者まで飛ばす。
- ライフ0の参加者を配布、宣言参加資格、開始者、現在手番から除外する。
- ラウンド番号を1増やし、前ラウンド結果と宣言履歴を破棄して、残存参加者へ再配布する。

終了条件未達で残存参加者が2名以上の場合だけ開始できる。同じ結果からの二重開始は、最初の成功後に状態が`Declaring`となるため拒否する。

## ゲーム勝敗

- ユーザーのライフが0になった時点で、NPCの残存数にかかわらずユーザー敗北とする。
- ユーザーが残存し、NPC4名が全員脱落した時点でユーザー勝利とする。
- それ以外は勝敗未確定とし、次ラウンドへ進める。

`GameOver`では最終ラウンド結果と最終勝敗を保持し、新規ゲーム開始とタイトル復帰以外を拒否する。

## 再戦とタイトル復帰

`GameOver`からの新規ゲーム開始では、既存モデルを巻き戻さず、参加者、デッキ、宣言フェーズを新規生成する。注入済み乱数源は継続利用する。再戦後は全員ライフ3・脱落なし、ラウンド番号1、宣言履歴なし、結果なし、勝敗未確定となる。

進行中の直接リスタートは受理しない。`Declaring`または`RoundResult`から新しいゲームを始める場合は、先にタイトル復帰を行う。

タイトル復帰は`Declaring`、`RoundResult`、`GameOver`で受理し、参加者、デッキ、配布、宣言、手番、ラウンド結果、最終勝敗を破棄して`NoGame`へ戻る。`NoGame`での重複復帰は状態不変で拒否する。

## Version 1の対象外

- 参加人数の設定
- NPC固有の判断アルゴリズム
- 画面レイアウト、入力部品、演出
- セーブとロード
- オンライン対戦
- 進行中ゲームの直接リスタート
